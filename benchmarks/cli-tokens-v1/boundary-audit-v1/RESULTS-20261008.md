SEMAPRAX S01, S02, and S04 pass all 16 checks; every TypeScript candidate passes
all 16. SEMAPRAX S03 and S05 each pass 14/16. Both fail only the literal-plus
timezone fixture in text and JSON. The frozen SPEC requires `+ZZZZ`; these
candidates also accept `-0000` and `-0530`, matching the historical oracle's
broader sign grammar. Expected output has 7 lines, 2 requests, and 5 malformed
lines; both actual outputs have 7 lines, 4 requests, and 3 malformed lines.
The mismatch changes totals, paths, and hours. Candidate S03 explicitly admits
both ASCII sign bytes at `loglens.spx:73`; S05 does so at `loglens.spx:52`.

S01–S03 execute native binaries. S04 uses the SEMAPRAX interpreter and passes.
S05 uses the interpreter through a Node chunk transport. Its `transport.mjs`
calls compiler `run`, validates `end:length` framing, propagates failures, and
concatenates SPX-generated byte chunks. SPX computes report content and splits
it at UTF-8 boundaries (`loglens.spx:328–339`). The JavaScript adapter performs
no log parsing, aggregation, arithmetic, or report formatting. Its failure is
the timezone grammar, and interpreter execution remains eligible under the
original compile-or-validate prompt.

The six offline audit unit tests pass. Candidate build plus comparison time
totals 70.812 seconds; the longest comparison takes 2.638 seconds. These timings
describe qualification execution, not the paid agent campaign or compiler speed.

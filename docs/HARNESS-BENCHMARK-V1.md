# Harness benchmark v1 (HP-17)

Status: additive development-harness specification (HP-17); local macOS aarch64 evidence only.

Audience: harness-provider maintainers deciding whether an integration may be
enabled automatically. Owner: `crates/semaprax-harness/src/bench/`; verb
`semaprax harness bench <corpus-dir>` (also `semaprax-harness bench`). Schema
`semaprax.harness-benchmark.v1`; corpus schema
`semaprax.harness-benchmark-corpus.v1`. Diagnostics `SPX-HPQ001..`.

The goal is completed development work, not a favorable compression figure. A
provider is admitted for a task scope only when it passes the gates below on
measured evidence. The benchmark may, and on weak evidence must, conclude that
an integration stays opt-in or disabled. It makes no claim of universal
superiority, and #309's broader case study stays independent.

## Gates (declared before any recorded result)

The constants live in `src/bench/gates.rs` and a test pins this section to
them. They were fixed before the first recorded run and are not tuned after
results. "Scope" is one (profile, task family) pair; gates G4-G6 are evaluated
over matched cells only: the same task and trial run by both the profile and
the baseline.

| Gate | Rule |
| --- | --- |
| G1 | Zero protected-fact loss. Every seeded adversarial case is detected, and measured cells show zero false negatives (a missing critical fact in a view that claims completeness, a claimed absence of existing callers, a forbidden route choice). |
| G2 | No permission widening. The machine-local grant file is byte-identical before and after the cells, and the descriptor-widening case is detected (a widened descriptor does not run on the old grant). |
| G3 | No hidden command replay. Every command cell shows exactly one execution on an independent counter file, and the double-execution case is detected. |
| G4 | Task quality. Accepted-rate delta against the baseline is at least -0.0 (no loss at all) over at least 10 matched cells. |
| G5 | Net cost. Model-visible bytes, including incurred requests (detail retrievals, router requests), fall by at least 20% against the baseline over at least 10 matched cells. |
| G6 | Latency. Added end-to-end latency per matched cell, cold and warm trials together, is at most 2000 ms, over at least 10 matched cells. |
| G7 | Tested. Every cell of the scope ran with the real tool: no untested and no failed cell. |

A scope is eligible for an automatic default only if G1-G7 all pass. A passed
gate is evidence on this corpus and these trials; zero observed failures is
not proof of safety and bounds nothing about unseen inputs. Missing tools,
models and platforms are `untested` cells, never wins; a failed provider is a
`failed` cell with its reason.

## Corpus (pinned)

`tests/fixtures/bench/corpus.json` (regenerated by `gen_corpus.py`, never
hand-edited) holds projects, tasks, profiles and seeded cases. Every project
directory is pinned by a tree digest of sorted relative paths and file
contents plus the source commit; a drifted fixture is refused before any cell
runs (`SPX-HPQ004`).

Projects: `downstream` (the ledger package used by the workflow harness, with a
real failing test), `mixed` (the calculator project with Rust, TypeScript and
Markdown beside `.spx`), `harness-src` (a verbatim excerpt of this crate's
observation and decision modules, the real Rust codebase used for orientation
and API-reuse tasks) and `scripts` (a deterministic noisy test-run script with
one failure buried in 320 tests and an execution counter).

Task record: `id`, `family` (`orientation | api_reuse | mechanical_refactor |
failing_test_diagnosis | multi_file_repair | law_effect_change`), `project`,
`request`, `authority {read, write: none|candidate, publish: false}` (the
benchmark never grants publication), `query`, `baseline_files` (what an
unassisted agent would read), `required_facts` (strings that must appear in the
model-facing context), `acceptance` (list of checks, all must pass) and
`budget`. Checks: `facts`, `references` (expected callers, no claimed
absence), `command` (critical lines must survive one execution), `workflow`
(compiler-judged status of a pinned proposal) and `route` (allowed and
forbidden options). Acceptance is deterministic: compiler and host verdicts and
string presence, never a model's opinion.

Profiles are configuration only: a `semaprax.harness.toml` selection plus
adopted descriptors, adopted and trusted through the ordinary `adopt` and
`trust` verbs, with tool paths from `HARNESS_*` variables. Core code contains
no product names or vendor branches. Shipped profiles: `native-only`
(baseline: compiler context, raw command view, rules decision),
`native+source-index` (the third-party example adapter, same contract),
`native+graft`, `native+graphify`, `rtk` (raw versus command view), `laya`
(rules versus learned router) and `local-efficient` (native + Graft + RTK +
rules). A profile only runs tasks whose steps it can change; the combined
profile is an ablation of its parts and is compared on the tasks each part
touches, never credited with the sum of per-plugin savings.

## Measurements

Per cell: accepted (all checks), critical-fact retention, false negatives,
model-visible bytes (`byte-v1`, UTF-8 bytes of the final envelope the model
receives) and bytes per accepted task, calls, retries, detail retrievals
(counted and incurred), latency per step, cold (trial 0, caches and retention
purged) versus warm trials, child-process CPU user/sys and max RSS from
`/usr/bin/time -l` around one cell process, and bytes left behind in the
harness cache and retention directories. p50/p95 use the nearest-rank
percentile; acceptance rates carry a Wilson 95% interval; byte standard
deviations across trials are reported.

No named tokenizer is available on this machine: every figure is byte-only and
labelled so. Byte counts are never presented as model tokens or billing. Cost
per accepted task is therefore reported as bytes per accepted task; provider
billing is not observed.

Attribution uses `observe::Observer` and `build_report`. The headline is the
end-to-end paired payload (unassisted baseline bytes against the final
model-visible envelope); incurred requests are subtracted once; the summary
fails reconciliation (`reconciliation_mismatches`) if stage-local reductions do
not sum to the end-to-end figure, if baseline minus final does not equal it, if
net does not equal reduction minus incurred, or if observer totals differ from
an independent sum over the raw cells. Host traffic is declared with the
workflow runs as unobserved, so the report is honestly `partial` and no
whole-task claim is made from it.

## Seeded adversarial cases

Each case plants a defect, and the benchmark must detect it. Ground truth is an
independent read of the fixture files.

- `missing_callers`: a provider that skipped files claims `no_references`
  (refused by the contract, `SPX-HPA040`), and an honest partial index; neither
  may yield `definitive_absence`.
- `hidden_critical_error`: a provider view says "all tests passed" with
  `lossless: true` while one failing line was dropped; the host must restore the
  line and mark the view incomplete.
- `stale_graph`: an index frozen before an edit offers old spans; none may be
  presented as verified.
- `wrong_router_choice`: a router names an option screened out by policy and an
  option that was never offered; the decision must fall back to rules.
- `double_execution`: a view provider that crashes or fails must not cause a
  second execution (independent counter file).
- `law_weakening`: a candidate deleting an `ensures` or widening `uses` is
  refused (`SPX-HPD042`, `SPX-HPD043`); with a compiler, a proposal that sets its
  own requirements is refused (`SPX-HPD032`).
- `permission_widening`: a descriptor widened after approval does not run on the
  old grant.

## Model trials

Real model-in-the-loop evidence needs at least ten matched independent trials
per claimed task and configuration. Paid or remote trials are not authorized
here. An optional local pilot (`--pilot HOST:PORT --pilot-model NAME`) sends the
context each profile produced to a loopback model and scores the answer by
required strings. Fewer than ten trials per configuration is labelled
`pilot-only` and supports no default. Seeds, model name and digest, and
temperature are recorded; only loopback endpoints are accepted.

A second pilot (`--pilot-skill-reps N`, default 6 per arm) asks a loopback model
for the body of a new helper with and without the adopted
`reuse-before-generation` skill block and scores deterministically whether the
answer reuses the existing declaration. The context is identical in both arms;
only the skill prompt block (as `skills --json` renders it, bytes counted as
incurred cost) differs. The total pilot budget is `--pilot-calls` (default 60).
Compiler gating is shown by deterministic cells, not by the model: the
`native+skill` profile runs every workflow task with skills enabled and
requires the same compiler-judged statuses and an unchanged `semaprax.toml`
(`no-dependency-change` check on every workflow cell).

## Explicit acceptance cells

- Workflow-driven external context: task `repair-ledger-polyglot` runs the
  development workflow (`run`, external context `always`) on a mixed-language
  project; the report records which provider the workflow itself invoked, the
  context bytes the workflow used against the full-source reference, and the
  required facts verified in the broker context for the same seed (the `run`
  report carries bytes and identity, not item text).
- Adopted skills: `adopt --skills <root>` plus `[skills] enabled = true`, the
  prompt cost, and the unchanged compiler gates, as above.

## Reproduce

Build the host once, then provide tools explicitly (nothing is discovered):

```sh
cargo build --offline -p semaprax-harness
export SEMAPRAX_COMPILER=<abs path of a built semaprax>
target/debug/semaprax-harness bench crates/semaprax-harness/tests/fixtures/bench \
  --work "$PWD/target/benchwork" --out benchmarks/harness/<date>-local --label "<date> local" \
  --env HARNESS_PYTHON=<abs python3> --env HARNESS_NODE=<abs node> \
  --env HARNESS_GRAFT=<abs graft> --env HARNESS_GRAPHIFY=<abs graphify> --env HARNESS_RTK=<abs rtk> \
  --pilot 127.0.0.1:11434 --pilot-model <local model> --pilot-profile native-only \
  --pilot-profile native+source-index --pilot-profile native+graft      # optional local pilot
```

`--profile NAME` (repeatable) restricts profiles (the baseline always runs),
`--warm N` changes warm trials, `--json` prints the machine summary. Outputs
in `--out`: `REPORT.md`, `summary.json` (with gates), `cells.jsonl` (one JSON
object per cell), `observations/<profile>.jsonl` (metadata-only
`semaprax.harness-observation.v1` events: no payload text), `environment.json`
(OS, tool and adopted-upstream versions, corpus digest). Delete `--work` after
recording numbers: it holds provider indexes. The deterministic fixture suite
runs without real tools or a model:
`cargo test --offline -p semaprax-harness --test harness_v1 bench::`; the cell tests need the real compiler
(`SEMAPRAX_COMPILER`) and are `#[ignore]`: add `-- --include-ignored` with it set.

## Support labels

A report must separate: tested local support (cells that ran here), protocol-only
hosted support (not benchmarked), untested platforms (Linux, Windows) and
historical evidence (cited, never mixed into these numbers).

# Host compiler retained-receipt observation v1

Status: bounded host implementation with synthetic offline controls. Actual compiler receipt/host integration qualification, independent execution and OPT606 completion remain pending. No model/provider or compiler was executed for the offline evidence.

This additive host route consumes [compiler retained receipt v1](JSON-CODEC-RETAINED-RECEIPT-V1.md) only when an agent explicitly invokes single-codec `json-codec ... --retained-receipt`. It does not change ordinary source output or rewrite argv to request a receipt automatically. Fresh CLI/LogLens and webapp-v2 harness source inventories pin `benchmarks/compiler_retained_receipt.py`; ShiftSim inherits the CLI inventory. Legacy immutable tool inventories lacking that optional helper retain their old capture behavior. If any supplied immutable tool inventory names the helper, all supplied inventories must bind its exact source hash. The pinned helper is copied beside the retained proxy, never imported from candidate code.

The real compiler still runs only in the agent's original sandbox, cwd, environment, standard streams and process group. The proxy hashes the configured executable before invoking it, checks the immutable plan's binary hash, and hashes it again after completion. A domain-separated length-prefixed digest binds actual filesystem-encoded executable spelling, every argv element and cwd. Its observation binds both binary hashes, invocation digest and returned process status. A failed compiler or failed capture keeps the original attempt status and cost numerator. No runner-side compiler, shell, cache search, download or provider invocation is added.

The existing broker retains the explicitly declared output through no-follow handles. In receipt mode that artifact is named `compiler_receipt_artifact`, never a complete mixed `.spx` output. It validates the raw artifact against the closed compiler schema and configured invocation, before-selected manifest/schema bytes, complete ordered manifest-declared held input inventory, source hashes, original/candidate path closure, unchanged unselected candidate sources, selected record/profile/bounds/output and both same-revision serialized bundle hashes. JSON duplicates, unknown fields, escaping paths, incomplete/duplicate inventories, malformed integers, rehashed unselected drift, mismatched binary/status/invocation and invented independent-execution/binary-self-authentication claims refuse adoption. The host retains its existing8 MiB per-snapshot bound even though the compiler protocol permits a larger artifact. An oversized artifact is a measurement refusal, never new authority.

The broker writes one runner-side `compiler-receipt-adoption.json` under that request. Its exact SHA is bound by the existing runner request receipt and summary. Later accounting reads only the closed retained artifact/report paths and hashes; live candidate replacement or deletion is not a fallback input. Report/receipt drift fails closed. An invalid receipt retains an `adoption_failed` observation alongside the actual attempt, without an optimistic substitution.

The observation schema is `semaprax.compiler-retained-receipt-observation.v1`. It distinguishes structural validity and compiler-reported complete held originals/same-revision repeat from trusted process origin. The mailbox remains agent-writable. A binary hash and internally consistent JSON do not independently prove that the binary emitted those bytes. Therefore `execution_independently_authenticated`, `semantic_replay_performed_by_host`, `input_closure_complete`, `exact_compiler_input_binding` and `ratio_eligible` remain false; independent execution, generated-source classification, billed cost and fixed-context counts remain null. Package version is compiler-reported compatibility only. There is no claim that before/after executable checks alone remove every execution race.

Three complete inventories stay separate: compiler-reported original held files (including exact original manifest and dependency envelopes), resolved original source closure, and full mixed candidate sources. Each file's exact retained UTF-8 bytes is tokenized only through the existing pinned legacy-Claude BPE proxy. Missing tokenizer keeps counts null for offline/calibration use; the existing scored-launch readiness gate remains authoritative. Broken runtime or invalid counts refuses measurement. The report never subtracts independently tokenized strings, labels proxy counts as GPT/NET tokens, infers pure generated authorship or accumulates repeated generations as authored totals. Existing final-file, failed-cost, billing/null and v1 provenance policies are unchanged.

Closing606 still requires executable compiler/host qualification and a lawful trusted in-sandbox invocation/output-origin binding (plus any independent-execution obligation), full original/mixed policy replay and matched live evidence where required. Those requirements cannot be earned by accepting agent-authored mailbox fields or by running a second compiler outside the existing sandbox.

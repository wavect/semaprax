# Immutable checked cache source custody (OPT-796)

Status: retained evidence; the recorded scope and qualification below apply.

Audience: compiler contributors, tool authors, and reviewers.

The current route preserves the original mutable provider, pruning and restore passes. It pays actual new source-owner headers, retained ordinal backing and one immutable parsed-owner directory on the real original core payer before acquisition. After restore, the actual programs and complete source metadata move into their owners. Ordinary Project linking uses those parsed owners for Agent/law extraction instead of reparsing. Checked keys keep generated roots separately and cannot expose or encode a source until their exact invocation slot completes. No combined Function/type receiving directory is created for admitted borrowed overlays. Unsupported profiles retain the complete owning route.

File facts and public Project source facts retain source metadata, which has no AST link. Explicit cache keys may retain their own exact parsed generation. Source values and the historical Program wire are unchanged. Source cache publication validates the complete directory and all pending key associations before binding; no failed build commits the caller cache.

The source owner phase prepays only actual new backing and inline payer carriers. It neither claims old raw-clone allowance nor supplies another quota or refunds. Deferred acquisition consumes its captured original payer, including sticky zero authentication, even after an outer context is restored. Snapshot replay retains its original ambient payer; its real owner acquisition uses the original canonical payer, whose final consumed snapshot follows reception.

The original AST lookup and retention bodies compile independently with a source-equality test. The complete old core and old materialized key receiver remain compiled; old source files are hashed under source-provenance.json. This is an independent old receiver comparison with shared unchanged provider/assembly boundaries, not a newly independent frozen whole Project driver.

No Cargo, tests, builds or Clippy ran here. Actual 5a81 stage17 differences (1344/1960) motivated this change; their elimination and application fit remain unverified. The two unchanged exact stage debit controls, complete cold/warm graph and image controls, original #795 hostile controls and snapshot controls remain mandatory. Source layout and newly charged common storage can change first byte refusal; no old byte-boundary equivalence or total allocator claim is made.

# Owned-provider ordinary-validation receipt

Status: focused local CI repair; hosted CI qualification remains incomplete.

Audience: compiler maintainers and CI reviewers.

The original GEN-05B package case on main `295c73b48f00a75eadf1f859c98bd41845dd7b0a` exhausted the native provider account during a repeated full HIR validation. The provider previously validated the same immutable program three times: upfront, during descriptor call-index reconstruction, and during native emission.

A private live receipt now retains the exact immutable program borrow after complete ordinary HIR validation. Descriptor replay still parses the complete closed descriptor, checks its digest, reconstructs every call-index map and descriptor field, and compares complete canonical bytes and digest. Native emission consumes its private receipt and accepts it only for the same program and owned Bytes or UTF8 profile. Raw public entry points retain complete validation; selected and proof-only owners cannot mint this receipt. It carries no storage or publication authority.

A new one-short reserved-floor control exposed a pre-existing partial-text publication path. After upfront validation, provider rendering now uses a child account limited to the actual allowance above the floor, with no soft trailer lane. The child settles its actual debit into the original parent. A refused child is discarded and its first requested amount and stage propagate into the parent sticky refusal. Successful complete generated bytes remain identical.

No budget, reserved floor, fixture, IR layout, successful generated provider bytes, public interface, or hostile-input validation is relaxed. The default native provider account remains 4 MiB with its existing 2 MiB wrapper reservation. Full predecessor implementations are retained in test-only modules. Tests compare complete provider artifacts for both profiles and prove that the debit reduction is exactly two isolated full HIR validations. Controls exercise zero and one-short allowances, the reserved floor, exact success, malformed HIR, descriptor drift, sticky refusal, foreign program identity, and wrong output profiles.

Verification results and acquisition details are recorded in `verification.json` and the accompanying logs. The original complete C/C++ package module runs against the genuine normal current production compiler, with all eight cases including the maximum export inventory. The focused native test binary uses the complete genuine compiler and IR; only unrelated test registration attributes are disabled. It does not qualify the complete Cargo test binary, hosted Linux or Windows, or the remaining graph-budget failures.

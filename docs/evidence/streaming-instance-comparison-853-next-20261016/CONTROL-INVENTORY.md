# Actual receiving boundaries

Status: historical source evidence; qualification is limited to the recorded revisions and results.

Audience: compiler contributors and reviewers.

`instance_match::CONTROLS` admits two concrete Compare owners (initializer and
named receiver), retained-ID method reference, three string references
(as_str return, constructor parameter, as_bytes receiver), header fmt result
and expect receiver, header mutable writer reference, admission/final boolean
values and empty-slice reference. Compare owns the one completeness bool. Its
first-omission bank is independent of the comparison byte predicate.

`KEY_CONTROLS` admits the caller and checked-method completion references
before `&mut output.complete` formation and the new payment boolean. The
ResolvedType method receiver and String result replace the original reached
identity_key method receiver and String result; neither is an additional
owning wrapper. If this admission fails, exactly one original key producer
still runs for that argument, and all later arguments still run.

The checked key method repeats the complete old iterative traversal. Every
nominal Finish first admits CheckedCappedString initializer/receiving/consuming
owners, caller/parameter/field completion references and admission boolean.
It uses the same current-or-captured byte sink and the same byte request.
Refused new constructor admission uses the original nominal producer in place,
not a second traversal. No child status vector or per-child result is added.

Each actual checked write admits its extra ENTRY call controls. The explicit
formula traces the successful extra reserve_active_required invocation through
active Rc/Ref/Option views, overflow, reserve, reserve_optional, checked_add,
Cell getters/setter and scalar receiving sites. This call is additional to the
surviving original reserve_sink byte invocation; its controls are not credited
against that call. Entry failure is an initial metadata-admission ABI boundary:
its failed debit is not claimed to have prepaid its own internal capture.
It sets the already owned root flag false and returns the old fmt::Result shape.

After successful entry admission, actual byte refusal invokes the existing
required-refusal operation once. FIRST_FAILURE_CONTROLS independently covers
its active capture/selected Rc, requested length argument, first receipt/site
and Cell receivers. The actual omitted byte length is recorded; a prior
absolute refusal remains selected. There is no recurring completion predicate:
subsequent callbacks fail their required ENTRY admission under the sticky
ledger and never reconstruct this first-omission transition. All callbacks and
later key producers still execute and return Ok. No reserve failure is retried
with another allowance.

Each actual comparison write admits its byte-prefix predicate, byte-slice
receivers, byte length/range and additional as_bytes string reference before
forming them. Its incoming writer/value/result roles correspond to the old
CappedString formatting boundary. The new header format corresponds to the
old final format header; per-argument key/length formatting is unchanged.
The encoded-tail and final identity backing are actually absent, not refunded
or retained as credit for unrelated roles. The derived billing and physical
allocation tradeoff remains unexecuted; common small cases can be worse.

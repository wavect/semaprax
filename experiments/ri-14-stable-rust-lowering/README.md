# RI-14 stable-Rust lowering candidate

This isolated fixture is the smallest executable candidate for GitHub issue
#372.  It is handwritten Rust that states the rules a future lowering must
derive from checked Semaprax HIR and its canonical cleanup plan.  It is not
generated by SEMAPRAX, does not parse `.spx` input, and does not establish a
Rust-source backend.

The candidate covers one pure scalar island:

- left-to-right checked addition before a generic Rust callback;
- an explicit cleanup-plan vector carried by the frame;
- cleanup after success, arithmetic failure, and callback failure;
- a generic `std::iter::Iterator::map` call whose callback returns a selected
  status; and
- a negative control showing why Rust lexical `Drop` cannot replace a supplied
  cleanup-plan vector.

`src/main.rs` deliberately performs cleanup through `Option::take` and
`Owned::release`, not `Drop`.  The fixture's plan is `[left, right]`, while
lexical Rust drops values in reverse declaration order (`right`, then `left`).
This proves only that a lowerer must emit the checked Semaprax plan explicitly;
it does not choose a cleanup order for any actual Semaprax function.

The direct-rustc reproducer is pinned by `toolchain.lock` and does not invoke
Cargo, rustup, a nightly feature, a dependency resolver, or a network service.
It writes its output under a temporary directory.  Run it only after the
reserved build/test slot is released:

```sh
RUSTC=/absolute/path/to/rustc ./reproduce.sh
```

Passing this fixture would be limited local evidence for the candidate source
semantics.  It does not compare C11 and Rust traces from the same checked HIR,
measure a bridge, or make any target or support claim.  Those gaps are listed
in [`NEXT-STEPS.md`](NEXT-STEPS.md).

The nondefault `unstable-rust-source-lowering` feature now exposes
`stable_rust_lowering::lower_i64_literal`.  It validates a real
`ResolvedProgram`, retains its canonical cleanup-plan schema, and emits Rust
only for a parameter-free `i64` literal with an inert ownership plan.  It
explicitly rejects every other signature, contract/effect, ownership action,
and expression shape.  The module is an emitter seam for the fixture, not a
route selected by the normal compiler.
